# Kexintong Public Demo

This repository reproduces the deterministic Kexintong analytical pipeline on five representative public-company samples. It is a methodological demo, not a product deployment and not an exact numerical reproduction of the private full-sample study.

## Collaboration status

This initial repository intentionally excludes `src/patent_scoring/` and all web-interface code. Those modules are reserved for a separate first contribution by the collaborator responsible for the patent valuation/NLP engine and front-end work. Until that contribution lands, the runner structure and BEP module can be reviewed, but the complete demo command is not expected to execute.

## Public demo scope

The public demo runs:

- schema-oriented CSV ingestion and financial-basis conversion;
- six-factor patent scoring;
- analytical break-even-point (BEP) analysis;
- sensitivity analysis and borrower segmentation;
- pricing recommendations and early-warning indicators.

The public demo never trains a machine-learning model. Its scores are normalized within the five-company demo universe, so they must not be interpreted as full-market percentiles or compared one-for-one with the private research report.

## Run the demo

```bash
python -m pip install -r requirements.txt
python scripts/run_demo.py
```

The command reads the bundled CSV files under `data/`, creates compatibility inputs under `data/generated/`, and writes the current results to `outputs/latest/`.

Output groups:

- `outputs/latest/reports/`
- `outputs/latest/figures/`
- `outputs/latest/interactive/`
- `outputs/latest/run_metadata.json`

The demo output intentionally contains no cross-validation score, model prediction field, model placeholder, or feature-importance chart.

## Scoring methodology

The six weights have one authoritative source: `src/patent_scoring/config.py`.

| Dimension | Weight |
|---|---:|
| Patent stock | 20% |
| Patent type quality | 12% |
| IPC heat | 20% |
| Recent patent CAGR | 13% |
| NLP similarity | 25% |
| Frontier-keyword density | 10% |

Financial flow data uses the explicit `value_basis` field first. `reported_cumulative_ytd` is converted to derived single-quarter flows; `reported_single_quarter` is retained. Heuristic inference is only a compatibility fallback when the field is missing, incomplete, mixed, or unsupported.

## Full research study

The private full-sample study is a separate workflow. It uses `GradientBoostingRegressor` (GBM), performs cross-validation, and may generate a GBM feature-importance chart. Historical research materials report a five-fold CV R² of `0.667 ± 0.113`; this value is not recalculated by the five-company public demo.

Research mode requires prepared private full-sample inputs:

```bash
python scripts/run_research.py --data-dir PATH_TO_PRIVATE_PREPARED_DATA
```

Research output is written separately under `outputs/research/` by default.

## Repository boundaries

- No website or UI code is included.
- No Wind batch interface is included.
- No private 50-company workbook is included.
- Frozen reference assets bundled under `data/reference/` are authoritative for the demo.
- `outputs/examples/` should contain only results freshly regenerated by the final public-demo code.

See `docs/methodology.md` for the complete scope and terminology decisions.
